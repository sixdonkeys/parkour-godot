# Decision: asset-pipeline

- **Options:**
  1. Commit all source art to git, keeping every file under 100 MB by splitting.
  2. Git LFS. Not installed on the Fedora laptop, and it adds a dependency for every clone.
  3. Keep large source art out of git: record each file's address and SHA-256 in `ASSETS.md` and a machine-readable `tools/assets.json`, and fetch them again with `tools/fetch_assets.py`, which checks every checksum. Commit only the small derived files the engine imports, and generated data with its generator and seed.
- **Sources:** `docs/survey/asset-pipeline.md` — godot-docs `importing_images.rst`; ProjectSettings class reference 4.7.2; Godot 4.7.2 `core/io/file_access_pack.cpp`; the brief's own note; local `vulkaninfo`.
- **Choice:** option 3.
  - **What git carries:**
    - Files of 20 MB or more go under `tools/cache/` (git-ignored), fetched by checksum from their source.
    - The imported copies the game uses live under `game/assets/`, reduced to what the best shipped profile needs. They are committed only while each stays under 50 MB and the repository's media stays reasonable.
    - Anything a generator can make again (terrain tiles, scatter tables) is regenerated by `tools/` from fetched sources and is not committed if it is large.
  - **Import settings:**
    - Textures: VRAM Compressed with mipmaps. Both `import_s3tc_bptc` and `import_etc2_astc` are on, so one import serves Linux/Windows (BC), the Mac universal build, and the M1 under Honeykrisp, which reports BC, ETC2 and ASTC.
    - Normal maps: flagged as normal maps. High-quality mode (BPTC/ASTC) is used for albedo where banding shows.
    - Meshes: LODs generated on import.
  - **Texture detail per profile:** set by the profile's limits (see `quality-profiles`), never by re-importing at a lower size. Source art stays at full resolution.
  - **Build size:** measured on the exported macOS `.zip` and `.app`.
  - **Packed-file list:** `tools/pcklist.py` reads the exported `.pck` (format v2–v4: header, then directory entries of path, offset, size, md5 and flags) and writes every path and size. `tools/build.py` checks that list against `ASSETS.md`:
    - Every packed path under `game/assets/` or `game/thirdparty/` must match an `ASSETS.md` entry by path or path prefix.
    - Everything else must be this build's own work (scripts, scenes, profiles, generated data) under a module folder.
  - **Licence records:** `ASSETS.md`, one entry per dependency or asset (or folder of one asset pack): source address, author, licence, the licence statement quoted from the source, SHA-256 of the fetched source, and what was changed.
- **Reason:** option 3 needs nothing beyond git and curl, keeps a fresh clone complete through one fetch command, and is the route the brief itself suggests. Parsing the `.pck` directly reads what really ships, rather than what the export filter was meant to include, so a planted file can't slip through.
